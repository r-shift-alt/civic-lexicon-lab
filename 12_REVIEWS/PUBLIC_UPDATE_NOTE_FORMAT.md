# Public Update Note Format

## Purpose

This note standardizes one lightweight public update format for the repository.

Use it when the project needs a visible sign of movement that does three things at once:
- shows what changed;
- points newcomers to the current review or contribution surface;
- states what help is useful right now.

The update note is a bridge, not a new artifact class.
It should help a reader act quickly without rereading internal planning material.

## When To Use

Use a public update note when:
- a new bounded artifact, packet, issue prompt, or review surface exists;
- the README should not absorb every incremental change;
- the repo needs a short linkable status post;
- a GitHub issue, discussion, README refresh, or direct outreach message needs a compact companion summary.

## Output Standard

Keep the note:
- short enough to scan in under a minute;
- concrete enough that a newcomer can follow the links and help;
- focused on the current artifact rather than broad project framing.

Preferred length:
- 120 to 220 words.

## Required Blocks

Every update note should answer four questions in this order:

1. **What changed?**  
   Name the concrete increment.

2. **What should someone read now?**  
   Link the smallest current review or contribution surface first.

3. **What help is useful right now?**  
   Ask for one bounded kind of contribution.

4. **What happens next?**  
   State the immediate follow-through if useful responses arrive.

## Guardrails

Do:
- lead with the current artifact or review surface;
- keep links minimal and specific;
- ask for one practical action;
- make the repo feel active and inspectable.

Do not:
- summarize the whole strategy stack;
- turn the note into a manifesto or roadmap dump;
- ask for vague “thoughts” or general debate;
- bury the current contribution path under too many links.

## Reusable Template

**Title:** `Update: [concrete artifact or review stage]`

**Body:**

`[Project or artifact]` moved forward with one concrete increment: `[what changed]`.

If you want the current review-ready surface, start here:
- `[smallest high-value link]`

If useful, then look at:
- `[supporting link 1]`
- `[supporting link 2]`
- `[supporting link 3]`

Right now, the most useful help is:
- `[one bounded contribution ask]`

If 2 to 3 practical responses arrive, they will be compressed into:
- `[next-step synthesis or decision link]`

## Reuse Note

This format can be reused as:
- a short GitHub discussion or issue-adjacent update;
- a README-linked “current status” post;
- a direct-outreach companion note;
- a lightweight repository progress marker between larger artifact releases.
