# Lexicon First Review Direct Outreach Bundle

## Purpose

This note turns the first review handoff into a ready-to-send direct outreach bundle for the pilot packet.

Use it when a live GitHub issue is not available or when the fastest path to the first 2 to 3 bounded responses is a small number of targeted messages to likely reviewers.

This is not a new review design.
It is the same bounded ask, compressed for direct outreach.

## When To Use

Use this bundle when:
- GitHub issue creation is blocked by missing auth or tooling;
- a likely reviewer is easier to reach directly than through public repo discovery;
- the goal is to get the first practical responses with minimal workflow overhead.

## Reviewer Target

Prioritize people closest to the actual user job:
- bilingual editors;
- translators;
- policy writers;
- communications staff;
- researchers or advisors who regularly move political language between German and English.

Avoid broad-interest outreach that invites theory debate instead of practical wording review.

## Outreach Rule

Keep the ask small.
Do not explain the whole project.
Do not expand into manifesto or strategy language.
Ask for practical review tied to wording, framing, translation, and explanation choices.

## Ready-To-Send Versions

### 1. Short Email Version

**Suggested subject:** `Quick review request: 3 draft German-English political lexicon entries`

Hi — I’m testing a small pilot packet for a German-English political concept lexicon.

The specific problem is practical: sometimes a German political term looks directly translatable into English, but the familiar equivalent quietly distorts the baggage, register, or practical meaning.

I’m looking for bounded review from people who actually work across wording, translation, editing, policy, or explanation.

If you’re open to it, please start here:
- `12_REVIEWS/LEXICON_PILOT_REVIEWER_PACKET.md`

Then skim these three draft entries:
1. `11_ARTIFACTS/LEXICON_SOLIDARITAET_ENTRY_DRAFT.md`
2. `11_ARTIFACTS/LEXICON_SOZIALE_MARKTWIRTSCHAFT_ENTRY_DRAFT.md`
3. `11_ARTIFACTS/LEXICON_STAATSBUERGERSCHAFT_ENTRY_DRAFT.md`

The review question is not whether you agree with the politics.
It’s whether these entries help with a real wording, translation, framing, or explanation decision.

If useful, please use the packet’s forced-use scenario and answer briefly:
- did this address a problem you actually recognize?
- which component was most useful?
- did any entry change the wording or explanation you would choose?
- what felt unnecessary?
- what is missing for practical use?

Short, rough notes are completely fine.
I’m trying to get the first 2 to 3 practical responses and then compress them into one review memo.

### 2. Direct Message Version

I’m testing a very small review packet for a German-English political concept lexicon.

The problem: some German political terms look directly translatable, but the familiar English equivalent can quietly distort the meaning or baggage.

Would you be open to a bounded review of 3 short draft entries?
Start with `12_REVIEWS/LEXICON_PILOT_REVIEWER_PACKET.md`, then skim the three linked entries on `Solidarität`, `soziale Marktwirtschaft`, and `Staatsbürgerschaft`.

What I need most: whether the entries help with a real wording / translation / explanation choice, what changed your wording if anything, what felt unnecessary, and what is missing.

Short notes are enough.

### 3. Super-Light Ask

Would you be willing to sanity-check 3 draft German-English political lexicon entries for practical translation/framing usefulness?

The question is simple: do they actually help with wording choices, or are they just analytical overhead?

If yes, I’d send one compact review packet plus the 3 entry links.

## Optional Reviewer Framing Line

Use this only if the reviewer needs one extra line of context:

This is a bounded pilot for a practical lexicon, not a request for broad theory or ideology feedback.

## Maintainer Sending Checklist

Before sending:
1. Use the shortest version that fits the channel.
2. Point to the packet first, not the whole repository.
3. Keep the request bounded to the three pilot entries.
4. Do not add new questions beyond the packet unless the channel absolutely requires it.
5. Prefer sending to 2 to 3 plausible reviewers over broadcasting widely.

After sending:
1. Save raw replies in a traceable local note or issue comment.
2. Do not synthesize after only one response unless the response reveals a critical failure.
3. Once 2 to 3 responses exist, fill `12_REVIEWS/LEXICON_REVIEW_SYNTHESIS_MEMO_TEMPLATE.md`.

## Reuse Note

If GitHub issue creation later becomes available, this bundle should not replace the issue draft.
Use `12_REVIEWS/LEXICON_FIRST_LIVE_REVIEW_SURFACE_GITHUB_ISSUE.md` for the public repo surface and keep this file as the low-friction fallback for direct reviewer outreach.
