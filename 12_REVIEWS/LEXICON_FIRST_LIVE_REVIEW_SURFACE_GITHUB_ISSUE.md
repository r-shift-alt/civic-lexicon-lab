# Lexicon First Live Review Surface: GitHub Issue Draft

## Purpose

This note turns `12_REVIEWS/LEXICON_FIRST_REVIEW_HANDOFF.md` into one posting-ready GitHub issue.

It is meant to be the first live review surface for the lexicon pilot packet when GitHub workflow is available.
If GitHub posting is blocked, the same body can be reused with minimal edits as:
- a GitHub discussion post;
- a direct outreach message;
- a small semi-public review request.

## Why This Surface

Use a single GitHub issue as the first live surface because it is:
- lighter than setting up multiple entry-specific issues at once;
- public enough to make the repo feel active;
- bounded enough to keep the first review ask focused on one packet;
- easy to link from README, CONTRIBUTING, or later update notes.

This surface is for first-response collection, not broad project debate.

1. Confirm the linked files are present in the public repo.

## Ready-to-Post GitHub Issue Body

**What this is**

I’m looking for bounded review on a small pilot packet for a German-English political concept lexicon.

The artifact is trying to solve one practical problem:
when a German political term looks directly translatable into English, but the familiar English equivalent may quietly distort the register, baggage, or practical meaning.

This is **not** a request for broad ideology debate or project-wide strategy feedback.
The question is whether these entries help with real wording, translation, framing, or explanation decisions.

**Who this review is most useful from**

Especially useful reviewers:
- bilingual editors;
- translators;
- policy writers;
- communications staff;
- researchers or advisors who regularly move political language between German and English.

**What to read**

Start with:
- `12_REVIEWS/LEXICON_PILOT_REVIEWER_PACKET.md`

Then review these three draft entries:
1. `11_ARTIFACTS/LEXICON_SOLIDARITAET_ENTRY_DRAFT.md`
2. `11_ARTIFACTS/LEXICON_SOZIALE_MARKTWIRTSCHAFT_ENTRY_DRAFT.md`
3. `11_ARTIFACTS/LEXICON_STAATSBUERGERSCHAFT_ENTRY_DRAFT.md`

If you want the fuller logic behind the packet, see:
- `12_REVIEWS/LEXICON_PROXY_REVIEW_ROUTINE.md`

**Forced-use scenario**

Imagine you are editing a short English explainer for readers who do not know German political vocabulary well.

The explainer mentions:
- calls for `Solidarität` in a social-policy debate;
- a party defense of the `soziale Marktwirtschaft`;
- a dispute over `Staatsbürgerschaft` reform.

For each term, decide:
- would you translate it literally,
- would you add a short gloss,
- or would you preserve the German and explain it?

Then note:
- what wording you would now use;
- what warning from the entry you would carry into the final text;
- where the draft still leaves you uncertain.

**Minimum questions**

1. Did this packet address a problem you actually recognize?
2. Which entry component was most useful: definition, mismatch note, framing warning, examples, or recommendation?
3. Did any entry change the wording or explanation you would choose?
4. What should be cut because it adds analysis but not use?
5. What is missing for practical use?
6. Would you want more entries in this format?
7. If you would not use this, what would you use instead?

**Short response template**

- Reviewer type:
- Do you recognize the problem? yes / no / partly
- Most useful entry:
- Most useful component:
- Did any entry change your wording choice? yes / no
- What did you change?
- What felt unnecessary?
- What is missing?
- Would you want more entries in this format? yes / no / maybe
- If no, what would you use instead?

**How to respond**

Reply in this issue with short, concrete notes tied to wording, examples, warnings, or missing guidance.
The response does not need to be polished.

**Maintainer follow-through**

Once 2 to 3 responses exist, they should be compressed into:
- `12_REVIEWS/LEXICON_REVIEW_SYNTHESIS_MEMO_TEMPLATE.md`

That memo should decide whether to continue, revise, or stop-or-demote the lexicon track based on actual review signals.
