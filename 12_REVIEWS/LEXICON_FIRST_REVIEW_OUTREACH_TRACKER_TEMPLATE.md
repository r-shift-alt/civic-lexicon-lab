# Lexicon First Review Outreach Tracker Template

## Purpose

This note provides the smallest execution sheet for the first live review push when the packet is sent through direct outreach rather than a GitHub issue.

Use it to keep the first 2 to 3 review requests bounded, traceable, and comparable.

It is not a new review design.
It is an execution aid for the existing packet, outreach bundle, and synthesis memo.

## When To Use

Use this tracker when:
- GitHub issue posting is blocked or still not the fastest route;
- the first review ask will be sent to 2 to 3 likely reviewers directly;
- replies need to be captured cleanly enough for later synthesis.

Primary materials to pair with this tracker:
- `12_REVIEWS/LEXICON_FIRST_REVIEW_DIRECT_OUTREACH_BUNDLE.md`
- `12_REVIEWS/LEXICON_PILOT_REVIEWER_PACKET.md`
- `12_REVIEWS/LEXICON_REVIEW_SYNTHESIS_MEMO_TEMPLATE.md`

## Use Rules

1. Keep the first pass to 2 to 3 plausible reviewers.
2. Pick the shortest outreach version that fits the channel.
3. Point to the packet first, not the whole repo.
4. Do not redesign the questions during outreach.
5. Capture replies in concrete wording, not memory-only summaries.
6. Do not synthesize after only one non-critical reply.

## Recommended Fields Per Reviewer

- reviewer label or initials
- reviewer type
- why they are a plausible fit
- channel
- outreach version used
- date sent
- response status
- follow-up date
- packet or entry focus if any
- raw-reply location
- synthesis-ready notes

## Trigger To Move On

Move to `12_REVIEWS/LEXICON_REVIEW_SYNTHESIS_MEMO_TEMPLATE.md` when:
- 2 to 3 usable replies exist; or
- one reply reveals a critical failure that clearly breaks the current packet.

## Resume Note

If the environment later supports live GitHub issue posting, do not discard this tracker.
Keep it as the direct-outreach path and use the GitHub issue draft as the public companion surface.
