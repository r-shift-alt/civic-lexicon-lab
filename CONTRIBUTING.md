# Contributing

Thanks for considering a contribution.

This project is trying to be useful before it tries to be expansive.
Please optimize for clarity, bounded scope, and inspectable value.

## Good first contributions

- tighten wording in the public README and docs
- suggest or refine candidate lexicon concepts
- add traceable source examples for German or English usage
- identify framing baggage, ambiguity, or false-equivalence risks
- improve review checklists for AI-assisted drafting
- propose cleaner separation between public collaboration material and internal planning material

## Contribution rules

1. Prefer small, concrete improvements over broad rewrites.
2. Ground claims in examples, sources, or operational reasoning.
3. Keep diagnosis, recommendation, and rhetoric clearly separated.
4. Do not turn the project into a manifesto or ideological branding exercise.
5. If proposing a new artifact, explain:
   - who it helps,
   - what recurring problem it solves,
   - how it stays bounded,
   - how usefulness could be reviewed.

## AI use

Heavy AI use is allowed and expected.
But contributions should still be reviewable.

If AI was used, contributors should aim to provide:
- the edited result,
- the reasoning for why it is useful,
- any key sources or evidence used,
- any uncertainty or likely failure mode.

## What not to do

Please avoid:
- vague theory expansion without a concrete artifact or method
- inflated language about transformation or disruption
- source-free synthesis
- premature platform design
- edits that collapse important language differences into false equivalence

## Review standard

A good contribution should make the repository:
- more useful,
- more legible,
- more testable,
- or easier for the next contributor to extend.
