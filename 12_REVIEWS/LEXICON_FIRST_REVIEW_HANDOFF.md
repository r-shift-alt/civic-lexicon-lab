# Lexicon First Review Handoff

## Purpose

This note is the smallest reusable handoff for the first lexicon review cycle.

It is designed to work in any of these surfaces without rewriting the whole request each time:
- a GitHub issue or discussion post;
- a direct outreach message to a likely reviewer;
- a semi-public review request shared with a small number of contributors.

The goal is simple: get the first 2 to 3 bounded responses to the pilot packet, then compress them with the synthesis memo template.

## Who This Review Is For

Prioritize people close to the actual user job:
- bilingual editors;
- translators;
- policy writers;
- communications staff;
- researchers or advisors who regularly move political language between German and English.

This is not a request for broad theory debate or ideological agreement.
The question is whether the entries help with real wording, translation, framing, or explanation decisions.

## Review Request

Please review this packet for practical usefulness, not ideological agreement.

The artifact is trying to help with one recurring problem:
when a German political term looks directly translatable into English, but a familiar equivalent may quietly distort the register, baggage, or practical meaning.

What matters most is whether the entries help you make a real decision more clearly.

## Forced-Use Scenario

Imagine you are editing a short English explainer for readers who do not know German political vocabulary well.

The explainer mentions:
- calls for `Solidarität` in a social-policy debate;
- a party defense of the `soziale Marktwirtschaft`;
- a dispute over `Staatsbürgerschaft` reform.

For each term, decide:
- would you translate it literally,
- would you add a short gloss,
- or would you preserve the German and explain it?

Then note:
- what wording you would now use;
- what warning from the entry you would carry into the final text;
- where the draft still leaves you uncertain.

## Minimum Questions To Answer

1. Did this packet address a problem you actually recognize?
2. Which entry component was most useful: definition, mismatch note, framing warning, examples, or recommendation?
3. Did any entry change the wording or explanation you would choose?
4. What should be cut because it adds analysis but not use?
5. What is missing for practical use?
6. Would you want more entries in this format?
7. If you would not use this, what would you use instead?

## Short Response Format

If helpful, use this compact template:

- Reviewer type:
- Do you recognize the problem? yes / no / partly
- Most useful entry:
- Most useful component:
- Did any entry change your wording choice? yes / no
- What did you change?
- What felt unnecessary?
- What is missing?
- Would you want more entries in this format? yes / no / maybe
- If no, what would you use instead?

## How To Return Notes

Use the lightest workable path for the surface where this handoff appears:
- reply in the GitHub issue or discussion thread;
- comment inline if the review is being run in a bounded issue prompt;
- or send a short written response back to the maintainer in the same channel where the request was shared.

The response does not need to be polished.
Short, concrete notes tied to wording, examples, warnings, or missing guidance are more useful than broad impressions.

## Maintainer Follow-Through

After at least 2 responses exist, compress them into:
- `12_REVIEWS/LEXICON_REVIEW_SYNTHESIS_MEMO_TEMPLATE.md`

That memo should capture:
- whether reviewers recognize the problem as real;
- which parts of the format changed actual wording judgment;
- what felt too dense or unnecessary;
- what is missing for practical use;
- whether to continue, revise, or stop-or-demote the lexicon track.
